# VYRDICT Beta Feedback Log

## Round 1 — August 20, 2026

**Invited:** 5 people  
**Responses received:** 3  
**Primary device mentioned:** Phone/mobile

### Tester 1

**What worked**
- Found the concept very interesting and useful.
- Already compares product feedback across multiple platforms when shopping, so having it consolidated in one place would save time.
- Understood the distinction between Viral Score and Worth Score immediately.
- Could see themselves using VYRDICT for product-shopping decisions.
- Said launching it would be doing shoppers a favor.

**Friction / suggestion**
- Mobile layout felt a little busy at first glance.
- Suggested more visual hierarchy and spacing to make the site cleaner and easier to scan.
- Explicitly framed this as a personal first impression, not a major issue.

**Action**
- Implement a restrained mobile-only hierarchy/spacing polish.
- No redesign, no new visual system, no feature changes.

### Tester 2

**What worked**
- Checked on phone.
- Liked the concept.
- Described the website as clean and modern.
- Found it easy to understand what VYRDICT does from the homepage.

**Action**
- Preserve the current visual direction.
- Treat Tester 1's density feedback as a light polish opportunity rather than a redesign signal.

### Tester 3

**What worked**
- Felt VYRDICT could be valuable for major purchases if it becomes a reliable information source.
- Said people already invest time researching before buying, so a trustworthy consolidated source has clear value.

**Suggestion**
- Consider adding a user score alongside Viral Score and Worth Score.

**Action**
- Defer User Score to post-launch/Phase 2.
- Do not launch a user score until there is enough real user volume to avoid misleading low-sample ratings.

## Round 1 Product Signals

- Core problem is validated: users already jump between platforms to compare product feedback.
- Value proposition is understood without explanation.
- Viral Score vs Worth Score is intuitive to testers.
- No tester reported a broken flow, unclear product purpose, or trust-breaking issue.
- Mobile scanability is the only repeated-worthy UX area identified so far, but feedback is mixed: one tester found it slightly busy while another described it as clean and modern.

## Decision Rules for Beta

1. Fix genuine bugs immediately.
2. Fix repeated usability confusion when a pattern emerges.
3. Make small polish changes when feedback is specific and low-risk.
4. Do not redesign based on one person's aesthetic preference.
5. Keep feature ideas in a post-launch backlog unless they solve a launch-critical problem.

## Post-launch Backlog

- **User Score / VYRDICT community recommendation score** — revisit after meaningful user volume exists. Potential format: percentage recommended + vote count, with minimum sample thresholds and anti-spam controls.
