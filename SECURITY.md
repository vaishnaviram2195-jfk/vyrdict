# VYRDICT Security

VYRDICT takes security and privacy reports seriously.

## Reporting a vulnerability

Please report suspected security vulnerabilities privately to **hello@vyrdict.com**. Do not open a public GitHub issue containing exploit details, credentials, personal information, or a working proof of concept.

A useful report includes:

- the affected page, endpoint, or feature;
- a clear description of the issue and potential impact;
- reproducible steps that avoid accessing or altering other users' data; and
- any relevant browser, device, request, or response details.

## Good-faith testing

Please do not perform testing that degrades service availability, destroys or changes data, attempts social engineering, accesses another person's account or private information, or bypasses controls beyond what is reasonably necessary to demonstrate the issue.

VYRDICT does not currently operate a public bug-bounty program and does not promise payment for unsolicited reports.

## Sensitive information

Never include passwords, authentication links, private keys, access tokens, personal information, or other secrets in a public issue or pull request.
